# Intalyzer

A tool for analyzing Arduino code for interrupt-related race conditions.

## Implementations

Intalyzer has two implementations. You can find more information in their respective README files:

| Implementation | Description |
|----------------|-------------|
| [intalyzer-clang](intalyzer-clang/README.md) | Clang tokenizer based implementation |
| [intalyzer-phasar](intalyzer-phasar/README.md) | Phasar based implementation |

## Dataset

The dataset used for testing and development can be found [here](https://drive.google.com/file/d/1-J-Wlwp9DBDmbpX6uSOML4jU50H8qG4z/view?usp=sharing). It contains 977 Arduino files found on GitHub that contain interrupts.

The dataset was generated by running [scraper.py](scraper.py) which scraped Arduino files from GitHub:
- The script first calls GitHub Search API to find Arduino files that contain interrupts.
- The script then downloads the files by calling GitHub APIs.

## AI Usage Disclaimer
Cursor IDE and various LLMs were used in the process of implementing `intalyzer-clang` to help deal with issues of clang tokenizer, in the process of implementing `intalyzer-phasar` to help deal with issues with LLVM, and other tedious tasks, speeding up development. The actual logic of identifying race conditions was written manually.
